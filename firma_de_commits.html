¿Qué es una Firma Digital?

Imagina que tu commit es un sobre con documentos importantes. Una firma digital es como un sello de cera con tu anillo único que se pone en ese sobre. Si alguien intenta abrirlo o cambiar los documentos, el sello se rompe y todos lo notan.

Llave Privada (Tu anillo)

Vive solo en tu computadora. Es secreta y se usa para "sellar" (firmar) tus commits. Nunca debes compartirla.

Llave Pública (El registro)

Se la das a GitHub. Es como un molde de tu sello. GitHub la usa para comprobar que el sello en el commit realmente es tuyo.

Metadatos

La firma no cambia tu código, solo viaja "pegada" al commit como una etiqueta invisible que dice "Yo hice esto".

Tu PC (Local) Firma con Llave Privada
Commit Firmado Viaja con la firma
GitHub Verifica con Llave Pública

¿Por qué es necesaria? (Seguridad)

Por defecto, Git es "confiado". No verifica identidades. Cualquiera puede escribir tu nombre y correo en la configuración y hacer commits que parezcan tuyos. Las firmas solucionan este gran problema.

  • El problema de Git: Los campos de nombre y correo son solo texto. No hay ninguna prueba real de que tú seas tú. Un impostor puede poner tu nombre fácilmente.
  • Evita la suplantación: Con las firmas, si alguien intenta hacerse pasar por ti, GitHub notará que la firma no coincide con tu llave pública y lo marcará como "Unverified" (No verificado).
  • Integridad del código: Garantiza que el código no fue alterado en el camino. Si alguien modifica aunque sea una coma, la firma se invalida automáticamente.
  • Auditoría confiable: Deja un registro histórico seguro. GitHub guarda la verificación de forma permanente. Si mañana alguien quiere saber quién hizo qué, el registro es 100% confiable.

Autoría y Validación

Cuando subes un commit a GitHub, el servidor hace una comparación matemática. Agarra la firma del commit y la compara con la llave pública que registraste en tu perfil.

Estado "Verified" (Verificado)

Hay una coincidencia exacta. La autoría está comprobada matemáticamente. GitHub muestra una insignia verde que da confianza a los revisores.

Verified

Estado "Unverified" (No verificado)

El commit no tiene firma o la llave no coincide. No hay prueba de quién lo hizo realmente. Es una señal de alerta.

Unverified

Dato importante: Una vez que un commit es verificado, GitHub guarda un registro permanente. Incluso si después borras tu llave por seguridad, ese commit del pasado seguirá mostrando "Verified" para siempre.

Creando tu Clave Local (GPG)

Para firmar, primero necesitas generar un par de claves criptográficas en tu computadora usando un programa llamado GPG. Es muy fácil:

# 1. Instalar GPG (si no lo tienes) # En macOS: brew install gnupg # En Ubuntu/Debian: sudo apt-get install gnupg # 2. Generar una nueva clave GPG gpg --full-generate-key

El comando gpg --full-generate-key es interactivo. Te hará unas preguntas, ¡responde así!

  • Tipo de clave: Presiona Enter para elegir "RSA and RSA".
  • Tamaño: Escribe 4096. Es el más seguro.
  • Expiración: Escribe 1y (1 año). Es buena práctica que caduque.
  • Nombre y Email: Pon tu nombre y usa el mismo email que tienes en GitHub.
  • Passphrase: Una contraseña segura. Te la pedirá cada vez que firmes.
# 3. Ver tu clave recién creada gpg --list-secret-keys --keyid-format=long # La salida será algo así: sec rsa4096/4AEA00A342C24CA3 2025-01-15 [SC] ... uid [ultimate] Tu Nombre <tu-email@github.com>

¡Atención aquí! Copia el texto que está después de la barra diagonal / en la línea que dice sec rsa4096/. En el ejemplo, es 4AEA00A342C24CA3. Ese es tu ID de clave y lo usarás enseguida.

Configurando Git y Exportando la Clave Pública

Ahora le decimos a Git que use tu clave para firmar, y sacamos una copia de la parte pública para llevarla a la nube.

# 1. Decirle a Git cuál es tu clave de firma (pega tu ID aquí) git config --global user.signingkey 4AEA00A342C24CA3 # 2. (Opcional) Firmar todos los commits automáticamente git config --global commit.gpgsign true # 3. Exportar tu clave PÚBLICA (en formato texto) gpg --armor --export 4AEA00A342C24CA3 # La salida será un bloque enorme de texto que empieza con: -----BEGIN PGP PUBLIC KEY BLOCK----- mQINBGO... ... -----END PGP PUBLIC KEY BLOCK-----

Copia absolutamente todo ese bloque de texto (desde donde dice BEGIN hasta END). Eso es tu llave pública, la que subirás a GitHub.

Nunca exportes tu clave privada. El comando siempre debe llevar --export (sin la palabra "secret"). La privada se queda siempre en tu PC.

Subiendo tu Clave Pública a GitHub

Entra a tu cuenta de GitHub y sigue estos pasos. Es como registrar tu firma en el notario de GitHub:

1

Ve a tu perfil de GitHub

Haz clic en tu foto de perfil (esquina superior derecha) y selecciona Settings (Configuración).

2

Accede a SSH and GPG keys

En la barra lateral izquierda, dentro de la sección "Access" (Acceso), haz clic en SSH and GPG keys.

3

Agrega una nueva GPG Key

Haz clic en el botón verde New GPG key. Se abrirá un formulario en blanco.

4

Pega y guarda

Dale un título (ej. "Mi Laptop"), pega el bloque de texto que copiaste en el paso anterior y haz clic en Add GPG key.

Flujo de Trabajo (3 Pasos)

¡Todo listo! De ahora en adelante, tu proceso para subir código seguro será este:

1

Firmar (En tu PC)

La clave privada en tu computadora genera la firma y la adjunta al commit. Usa el flag -S al hacer commit.

git commit -S -m "Tu mensaje de commit"

Si configuraste commit.gpgsign true en el paso anterior, no necesitas escribir el -S.

2

Subir (A la nube)

El commit viaja junto con su firma digital hacia los servidores de GitHub de forma normal.

git push
3

Verificar (Automático en GitHub)

GitHub recibe el commit, usa tu clave pública registrada para validar la firma. Si todo coincide, muestra la insignia verde.

Verified

Diccionario de Comandos

gpg --full-generate-key

Es el "asistente de creación". Abre un menú en la terminal para crear tu par de claves desde cero. Te pregunta qué tipo de seguridad quieres.

gpg --list-secret-keys

Es el "inventario". Te muestra todas las claves privadas que has creado en tu computadora. Sirve para buscar tu ID de clave.

gpg --armor --export [ID]

Es el "traductor a texto". Saca tu clave pública y la convierte en un bloque de letras y números que puedes copiar y pegar en GitHub.

git config --global user.signingkey

Es el "aviso para Git". Le dice a tu programa Git: "Oye, cuando te pida firmar, usa esta clave específica que te estoy dando".

git commit -S

Es la "acción de firmar". El -S (mayúscula) le dice a Git que firme ese commit en particular antes de guardarlo.

git config --global commit.gpgsign true

Es el "piloto automático". Si lo activas, todos tus commits se firmarán solos sin que tengas que escribir el -S cada vez.
