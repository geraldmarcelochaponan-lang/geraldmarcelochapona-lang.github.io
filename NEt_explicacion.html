Diapositiva 01 · Base

¿Qué es .NET y de qué está hecho?

Qué decir en voz alta

.NET es una plataforma que creó Microsoft para que los programadores puedan construir aplicaciones. Es importante aclarar desde el inicio que .NET no es un lenguaje de programación, sino el ambiente donde el código se ejecuta. Los lenguajes como C# se usan sobre esta plataforma.

Es una plataforma gratuita, de código abierto y multiplataforma: funciona en Windows, Linux y macOS sin tener que cambiar el código. Una aplicación hecha en .NET puede correr en cualquiera de esos tres sistemas.

Las piezas que forman .NET

CLR (Common Language Runtime)
Es el componente principal. Su trabajo es ejecutar el programa y administrar la memoria automáticamente, para que el programador no tenga que liberar memoria manualmente.
BCL (Base Class Library)
Es un conjunto de bibliotecas de código ya escritas que se pueden reutilizar. Por ejemplo: funciones para leer archivos, manejar texto, hacer conexiones de red. Evita empezar de cero.
Compiler (Compilador)
Es el programa que convierte el código que escribe el programador en un formato que la máquina puede entender y procesar.
SDK (Software Development Kit) + CLI (Command Line Interface)
Son las herramientas que permiten crear proyectos, compilarlos y publicarlos. Se usan desde la línea de comandos (CLI) o desde un editor de código.
NuGet
Es un repositorio o "tienda" donde los desarrolladores descargan librerías ya hechas por otras personas. Permite agregar funcionalidad extra sin escribir todo desde cero.
Con .NET no empiezas de cero: el runtime, las bibliotecas y las herramientas ya vienen incluidos. Tú solo escribes la lógica de tu aplicación.
Consejo para exponer: si alguien pregunta "¿entonces .NET es lo mismo que C#?", responde: "No. C# es el lenguaje; .NET es la plataforma que lo ejecuta. Es como la diferencia entre un idioma y el país donde se habla."

Diapositiva 02 · Herramientas

Lenguajes y tecnologías clave

Qué decir en voz alta

.NET no obliga a usar un solo lenguaje. Ofrece tres lenguajes principales, cada uno pensado para un tipo de trabajo distinto. Y también ofrece diferentes tecnologías según el tipo de aplicación que se quiera construir.

Los tres lenguajes

C# (C Sharp)
Es el lenguaje más usado en la industria. Con él se construyen desde aplicaciones web hasta videojuegos. Es la primera opción para la mayoría de proyectos.
F# (F Sharp)
Es un lenguaje enfocado en cálculos y procesamiento de datos. Se usa en proyectos donde la matemática o el análisis de información son importantes.
Visual Basic
Es un lenguaje que aún se usa en empresas que tienen sistemas Windows antiguos o desarrollos internos. Es más sencillo de leer y escribir.

Tecnologías según el tipo de aplicación

ASP.NET Core
Es el framework para crear sitios web y servicios de internet. Permite que una aplicación reciba peticiones y devuelva respuestas a través de internet.
Entity Framework Core
Es la herramienta para trabajar con bases de datos. Permite leer y guardar información sin tener que escribir consultas SQL manuales; se usan objetos en C#.
.NET MAUI (Multi-platform App UI)
Con un solo proyecto de código se puede crear una aplicación para Android, iOS, Windows y macOS. No hay que programar cada sistema por separado.
WPF (Windows Presentation Foundation) y WinForms
Son tecnologías para crear programas de escritorio en Windows. WPF es más moderna; WinForms es más antigua pero todavía se usa en empresas.
El lenguaje es el mismo para todos los proyectos. Lo que cambia es la tecnología que eliges según si haces una web, una app móvil o un programa de escritorio.
Consejo para exponer: aclara que se puede combinar. Un proyecto puede usar C# como lenguaje, ASP.NET Core para el backend y MAUI para la app móvil. No son excluyentes.

Diapositiva 03 · Motor

¿Cómo funciona por dentro?

Qué decir en voz alta

Cuando un programador escribe código en C#, ese código no se ejecuta directamente. Pasa por un proceso de traducción en dos etapas. Este proceso es lo que permite que el mismo programa funcione en distintos sistemas operativos.

Las cuatro etapas

1. Escribir el código
El programador escribe las instrucciones en C#. Es el código fuente que se ve en el editor.
2. Compilación a IL (Intermediate Language)
El compilador convierte el código C# en un lenguaje intermedio. Este lenguaje no depende del tipo de procesador, por eso es el mismo para cualquier máquina.
3. JIT (Just-In-Time)
Al momento de ejecutar, el JIT toma el código intermedio y lo convierte en código de máquina específico para el procesador donde corre el programa. Se llama "Just-In-Time" porque se hace en el momento necesario.
4. El CLR ejecuta
Finalmente el CLR (Common Language Runtime) ejecuta el programa y controla la memoria y la seguridad durante todo el proceso.
El código se compila una vez y se adapta al sistema donde corre. Por eso el mismo programa funciona en Windows, Linux y macOS sin cambios.
Consejo para exponer: si el público no entiende por qué hay dos compilaciones, di: "La primera compilación genera un formato universal. La segunda lo traduce al idioma específico de la máquina donde se ejecuta. Así el mismo archivo sirve en cualquier sistema."

Diapositiva 04 · Impacto

Rendimiento y unificación

Qué decir en voz alta

Hay dos cosas importantes que destacar de .NET hoy: es rápido, y ya no está fragmentado. Antes existían tres versiones separadas de .NET y los desarrolladores tenían que elegir cuál usar según el sistema. Desde .NET 5 hay una sola versión para todos los sistemas.

Rendimiento

En pruebas públicas de rendimiento (TechEmpower) que miden cuántas solicitudes web puede procesar un servidor al mismo tiempo, .NET ha demostrado procesar más solicitudes concurrentes que Node.js y Java. Esto significa que puede atender a más usuarios al mismo tiempo sin perder velocidad.

Unificación

Antes, un desarrollador tenía que elegir entre:

  • .NET Framework: solo funcionaba en Windows.
  • .NET Core: funcionaba en varios sistemas, pero era una versión separada.
  • Mono: pensada para aplicaciones móviles.

Desde .NET 5 hay una sola versión que unifica todo. Esto elimina la confusión y estandariza el desarrollo para todos los sistemas.

Hoy hay una sola versión de .NET para todos los sistemas, y está optimizada para manejar muchas solicitudes al mismo tiempo sin perder velocidad.
Consejo para exponer: si te preguntan "¿qué gana una empresa con esto?", responde: "Menos confusión al elegir versión, y un solo equipo puede mantener el mismo código para todos sus sistemas."

Diapositiva 05 · Futuro

IA nativa y Nube

Qué decir en voz alta

.NET ha incorporado dos tendencias muy importantes del presente: la inteligencia artificial y la computación en la nube. Esto significa que las empresas que ya usan .NET pueden agregar estas capacidades sin cambiar de tecnología ni reescribir sus sistemas desde cero.

Inteligencia Artificial

Semantic Kernel
Es una librería de .NET que permite integrar modelos de lenguaje (como ChatGPT) directamente en aplicaciones hechas en C#. No se necesita usar Python ni cambiar de lenguaje para trabajar con IA.

Esto permite que una aplicación empresarial existente pueda, por ejemplo, tener un asistente que responda preguntas usando inteligencia artificial, sin cambiar de plataforma.

Computación en la nube

.NET Aspire
Es una herramienta para crear, monitorear y desplegar aplicaciones distribuidas (varios servicios que trabajan juntos). Facilita la administración de sistemas en la nube.
Docker
Es una tecnología de contenedores que empaqueta una aplicación con todo lo que necesita para funcionar. .NET genera imágenes pequeñas y con arranque rápido, lo que ahorra recursos en los servidores.
Si tu aplicación ya está hecha en .NET, puedes integrarle inteligencia artificial sin migrar a otro lenguaje ni reescribir el proyecto.
Consejo para exponer: aclara que "nube" significa que la aplicación corre en servidores de internet en lugar de en una computadora local. .NET está diseñado para funcionar bien en ese entorno.

Diapositiva 06 · Cierre

Native AOT y conclusión

Qué decir en voz alta

Para cerrar, hablemos de una característica que está marcando el futuro de .NET: la compilación Native AOT. Después de esto, damos la conclusión general de toda la exposición.

Native AOT

AOT (Ahead-Of-Time)
Es una forma de compilación que traduce el código directamente al código de máquina antes de ejecutar el programa. A diferencia del JIT (que traduce en el momento), AOT lo hace todo antes.

Resultado: la aplicación arranca de inmediato y usa menos memoria. Es ideal para dos escenarios:

  • Servicios en la nube que inician y se detienen constantemente (como AWS Lambda o Azure Functions), porque el tiempo de arranque es casi cero.
  • Dispositivos con recursos limitados (Edge Computing), donde la memoria es escasa.

Conclusión general

.NET es una sola plataforma que permite construir cualquier aplicación moderna: web, móvil, escritorio, nube e inteligencia artificial. Incluye varios lenguajes (principalmente C#), herramientas completas y un rendimiento optimizado. Es gratuita, de código abierto y funciona en todos los sistemas principales.

Con Native AOT, la aplicación queda compilada para esa máquina específica: arranca de inmediato y consume menos memoria. Por eso sirve para servicios en la nube que se encienden y apagan todo el tiempo, y para dispositivos con poca capacidad.
Consejo para cerrar: puedes terminar diciendo: ".NET ya no es solo una herramienta para hacer páginas web. Es una plataforma completa que cubre las necesidades actuales de las empresas: nube, inteligencia artificial y rendimiento."
